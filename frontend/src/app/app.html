Method & model card

How it works

  1. 1DataIBM HR, {{ r.dataset.rows }} rows, 4 constant/ID columns dropped
  2. 2Feature engineeringmerge + 6 paper features, fitted on train only
  3. 3Clean & encodemedian / mode imputation, one-hot, StandardScaler
  4. 480 / 20 splitstratified, seed 42, test untouched
  5. 5Tune & select5-fold grid search, one-SE rule, nested CV
  6. 6Decidecost-sensitive threshold + recommendations
  7. 7ServeFlask API · in-browser engine · GitHub Pages

Paper-engineered features

Education_EducationFieldEducation level merged with field, e.g. “3_Medical”
Avg_Age_in_DepartmentMean training age of the employee's department
Age_CategoryYoung < 30 ≤ Middle-aged < 45 ≤ Old
Tenure_RatioYearsAtCompany ÷ TotalWorkingYears
Experience_Per_YearTotalWorkingYears ÷ Age
Salary_CategoryLow / Medium / High by training tertiles of income
HourlyRate_EfficiencyDailyRate ÷ HourlyRate (implied paid hours/day)

Implemented as a fitted sklearn transformer inside the saved pipeline, so the API and the browser accept the 30 raw form values.

Limitations & responsible use

  • Single, synthetic-style public dataset; {{ r.dataset.left }} leavers limits minority-class precision.
  • Correlations, not causes: recommendations are model what-ifs, not guaranteed outcomes.
  • Protected attributes (age, gender, marital status) are inputs; a fairness audit is required before real use. They are never recommended for change.
  • Decision support only — never the sole basis for HR decisions; discuss support with the employee.
  • Cost figures are illustrative defaults ($15k replacement, $1.5k intervention).
